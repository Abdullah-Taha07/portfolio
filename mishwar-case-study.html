05 / ROLE & REVIEW PROCESS

دوري في التطوير: من المتطلب إلى الدليل

في مشوار أساهم في تحديد السيناريوهات ومعايير القبول، وتوجيه التنفيذ بمساعدة Codex، ومراجعة تغييرات Git، وتشخيص أخطاء التكامل، وفحص نتائج الاختبارات قبل الموافقة على التعديل. هذا وصف لدوري في العمل وليس ادعاء بأنني كتبت جميع الملفات دون مساعدة.

01

تحديد ما يجب أن يحدث

مثال: لا يصح إصدار عرض سعر من مسار تالف، ولا منح موظف غير معتمد صلاحيات الإدارة. أوضح شروط القبول وأراجع السيناريوهات السلبية قبل اعتماد النتيجة.

02

مراجعة التغيير والسبب الجذري

أتابع الاختلافات بين الكود قبل الإصلاح وبعده، وأفحص سلوك HTTP وCORS والجلسات وبيانات الرحلات، وأطلب تصحيحًا عند ظهور تعارض بين التطبيقات الثلاثة.

03

التحقق والحدود

أراجع تشغيل الاختبارات ومسار الدمج وسجل الأخطاء. اختبار محلي ناجح يثبت السيناريو المختبر فقط، ولا يعني اختبار GPS ميدانيًا أو إطلاقًا تجاريًا آمنًا.

إجابة شفافة لمسؤول التوظيف: أستعين بأدوات برمجة مساعدة في كتابة أجزاء من الكود؛ هذه الأدلة تثبت وجود تنفيذ قابل للمراجعة واختبارات، لكنها ليست اختبارًا مستقلًا لقدرتي على البرمجة دون أدوات مساعدة. يمكنني شرح قرارات المشروع ومناقشة أمثلة الكود في مقابلة عملية.

Mishwar: from mobile experiences to a connected backend.

An experimental ride-hailing platform linking rider, captain and admin web apps to a shared backend. My work includes coordinating development, reviewing integrations and failures, testing changes and validating end-to-end consistency.

Project status: Development pilot — not an approved commercial transport service or a Google Play / App Store release.

03 / ENGINEERING WORK

Problems investigated

Permissions and identity

Test coverage for denying unapproved accounts access and checking employee permissions before sensitive operations.

Routing integrity

Tests reject malformed or untrusted route data rather than using invalid distances to generate fares.

Location and ETA reliability

Tests check location freshness and route-provider data to avoid presenting untrusted values as measured results.

04 / PROBLEM → DECISION → TEST

Three reviewable engineering decisions

These are code-backed tests, not commercial performance metrics. I use AI-assisted coding tools while contributing to requirements, review, debugging, test verification and integration; I do not claim to have handwritten every line.

01 · ROUTE INTEGRITY

Prevent untrusted routing data from pricing a trip

Problem: Corrupt or implausible road data can distort fares. Implementation: Validate routes and cached provider data before quoting. Evidence: Tests reject malformed routes and prevent quote creation when trustworthy data is unavailable.

02 · ACCESS CONTROL

Protect privileged operations from unapproved accounts

Problem: Staff roles should not inherit unrestricted privileges. Implementation: Check account activation, identity and permissions before sensitive actions. Evidence: Local tests cover pending employees, permissions and approvals.

03 · LOCATION TRUST

Validate driver location freshness and ETA inputs

Problem: Stale positions and unreliable route data can mislead riders. Implementation: Check freshness and provider data. Evidence: Local synthetic-data tests; not certified GPS accuracy on physical devices.

05 / ROLE & REVIEW PROCESS

My contribution: requirements, review and verification

On Mishwar I help define scenarios and acceptance criteria, direct AI-assisted implementation using Codex, review Git changes, investigate integration failures, and check test outcomes before accepting changes. This is a description of my workflow, not a claim that every line was written without assistance.

01

Define expected behavior

A bad route must not produce a quote; an unapproved staff account must not gain admin privileges. I focus on acceptance criteria and failure cases.

02

Review changes and investigate failures

I inspect diffs and investigate HTTP, CORS, session and trip-data inconsistencies across the three apps, requesting fixes when validation fails.

03

Verify and communicate limits

I review automated tests, merge records and errors. Passing offline tests supports specific scenarios, not field-tested GPS accuracy or commercial launch readiness.

For hiring teams: I use AI-assisted coding tools for parts of implementation. The repository and test links show reviewable work, but they do not independently validate my unaided coding ability. I welcome a technical interview to explain design choices and work through code.
